## 0. Critical Clarification: Frontier Models DO NOT Bring Their Own Tools

### The Fundamental Misunderstanding

There is a pervasive and dangerous misconception in the industry about how
frontier LLM "function calling" works. This section exists to eliminate that
misconception permanently.

**Frontier models (Claude, GPT-4, DeepSeek, Gemini, Llama) DO NOT bring their
own tools. They DO NOT execute code. They DO NOT have filesystem access. They
DO NOT make network requests. They are TEXT GENERATORS — nothing more.**

When documentation says "Claude calls a function," what actually happens is:

```
ACTUAL REALITY:
┌─────────────────────────────────────────────────────────────────┐
│  1. BugSwarm sends a prompt + tool definitions to the model      │
│  2. The model outputs TEXT, which happens to be valid JSON       │
│  3. BugSwarm parses this JSON to extract tool name + arguments   │
│  4. BugSwarm executes the tool using ITS OWN infrastructure      │
│  5. BugSwarm sends the tool result back to the model as TEXT     │
│  6. The model reads this text and decides what to output next    │
└─────────────────────────────────────────────────────────────────┘
```

The model never "calls" anything. The model generates a JSON blob like:

```json
{
  "name": "read_file",
  "arguments": {
    "path": "/src/auth.py",
    "start_line": 1,
    "end_line": 50
  }
}
```

That's it. That's the entirety of "function calling." The model produces text.
BugSwarm receives text. BugSwarm decides what to do with that text. If BugSwarm
chooses to interpret it as a tool call, BugSwarm executes the tool and sends
the result back.

### Why This Distinction Matters for Architecture

If you believe "the model has tools," you might design a system where tool
execution happens inside the model's context — which is impossible. Instead,
you must design a system where:

1. **Tool definitions** are metadata sent as part of the prompt or API parameters
2. **Tool calls** are JSON objects in the model's text output
3. **Tool execution** happens in YOUR infrastructure, never in the model
4. **Tool results** are formatted as text messages sent back to the model
5. **The conversation loop** is managed by YOUR system, iterating between
   model output -> your execution -> model input

The model has NO agency. It has NO access to anything outside the text you
provide it. Every "tool use" is actually BugSwarm performing a tool use in
response to a text pattern produced by the model.

### Concrete Example: What Actually Happens

User asks BugSwarm: "Find SQL injection in auth.py"

```
STEP 1: BugSwarm constructs a prompt:
  "You are a security agent. Available tools: read_file, grep, analyze_taint.
   Task: Find SQL injection in auth.py"
   
STEP 2: BugSwarm sends prompt to DeepSeek API

STEP 3: DeepSeek returns TEXT (not a function call, just text):
  "I'll start by reading the file. Let me check auth.py."
  Then DeepSeek outputs a special text block:
  <tool_call>{"name": "read_file", "arguments": {"path": "auth.py"}}</tool_call>

STEP 4: BugSwarm's parser detects the <tool_call> block and extracts:
  {name: "read_file", arguments: {path: "auth.py"}}

STEP 5: BugSwarm executes: fs::read_to_string("auth.py") -> "SELECT * FROM users..."

STEP 6: BugSwarm sends this result back to DeepSeek as a new message:
  <tool_result>File auth.py (150 lines):
  Line 23: query = "SELECT * FROM users WHERE id = " + user_input
  </tool_result>

STEP 7: DeepSeek reads this text and generates:
  "I found a SQL injection on line 23. The user_input is concatenated..."
  <tool_call>{"name": "analyze_taint", "arguments": {"file": "auth.py", "line": 23}}</tool_call>

STEP 8-11: BugSwarm runs taint analysis, sends results, model gives final answer
```

At NO POINT did DeepSeek execute any code, read any file, or access any system.
Every "action" was BugSwarm responding to text patterns generated by DeepSeek.

### Comparison With Actual Code Execution Models

Some models (like Code Interpreter in ChatGPT) DO have actual execution
environments. Those are entirely separate from function calling:

| Feature | Function Calling | Code Interpreter |
|---------|-----------------|------------------|
| Model executes code? | NO | YES (sandboxed Python) |
| Model accesses files? | NO | YES (sandboxed /mnt/data) |
| Model makes HTTP requests? | NO | Limited (within sandbox) |
| Who controls execution? | BugSwarm | The platform (OpenAI) |
| Where does execution happen? | BugSwarm's infra | OpenAI's servers |
| Artifact of execution | Text (JSON) in model output | stdout, files, errors |
| Model aware of execution? | Only through text results | Yes, directly |

**BugSwarm uses FUNCTION CALLING, not CODE INTERPRETER.** All execution happens
on BugSwarm's infrastructure, under BugSwarm's control, with BugSwarm's security
policies.

## 2. ToolRegistry to Provider Schema Mapping

### 2.1 Universal Tool Definition Format

BugSwarm defines tools in a provider-agnostic intermediate format:

```rust
/// Universal tool definition — provider-agnostic.
/// Stored in the ToolRegistry, converted to provider-specific schemas.
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct ToolDefinition {
    /// Unique tool identifier (snake_case, e.g., "read_file")
    pub name: String,

    /// Human-readable description for the model
    /// CRITICAL: This is the ONLY information the model has about the tool.
    /// Write clear, precise descriptions with usage examples.
    pub description: String,

    /// JSON Schema for the tool's parameters
    pub parameters: ToolParameters,

    /// Execution constraints
    pub constraints: ToolConstraints,

    /// Runtime metadata (not sent to model)
    pub metadata: ToolMetadata,
}

/// JSON Schema-compatible parameter definition.
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct ToolParameters {
    /// JSON Schema type (usually "object")
    #[serde(rename = "type")]
    pub schema_type: String,

    /// Required parameter names
    pub required: Vec<String>,

    /// Parameter definitions
    pub properties: HashMap<String, ParameterProperty>,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct ParameterProperty {
    #[serde(rename = "type")]
    pub param_type: String,
    pub description: String,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub enum_values: Option<Vec<String>>,
    #[serde(skip_serializing_if = "Option::is_none")]
    pub default: Option<serde_json::Value>,
}

/// Constraints that limit tool execution.
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct ToolConstraints {
    /// Maximum execution time in milliseconds
    pub max_duration_ms: u64,

    /// Required permission level
    pub required_permission: PermissionLevel,

    /// Maximum concurrent invocations per agent
    pub max_concurrent: u32,

    /// Allowed filesystem paths (for filesystem tools)
    pub allowed_paths: Vec<PathPattern>,

    /// Disallowed filesystem paths
    pub disallowed_paths: Vec<PathPattern>,

    /// Rate limit: max calls per minute
    pub rate_limit_per_minute: Option<u32>,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct ToolMetadata {
    pub version: String,
    pub category: ToolCategory,
    pub is_destructive: bool,
    pub requires_sandbox: bool,
    pub author: String,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
pub enum ToolCategory {
    FileSystem,
    CodeAnalysis,
    TestExecution,
    Search,
    Network,
    Sandbox,
    Configuration,
    Reporting,
}
```

### 2.2 Provider-Specific Schema Mapping

Each provider has a different JSON structure for tool definitions. The Gateway
abstracts these differences.

#### 2.2.1 OpenAI Function Calling Format

```json
{
  "model": "gpt-4-turbo",
  "messages": [...],
  "tools": [
    {
      "type": "function",
      "function": {
        "name": "read_file",
        "description": "Read the contents of a file at the given path",
        "parameters": {
          "type": "object",
          "properties": {
            "path": {
              "type": "string",
              "description": "Absolute path to the file to read"
            }
          },
          "required": ["path"]
        }
      }
    }
  ],
  "tool_choice": "auto"
}
```

OpenAI response format:

```json
{
  "choices": [{
    "message": {
      "role": "assistant",
      "content": null,
      "tool_calls": [{
        "id": "call_abc123",
        "type": "function",
        "function": {
          "name": "read_file",
          "arguments": "{\"path\":\"auth.py\"}"
        }
      }]
    }
  }]
}
```

BugSwarm must send the result back as:

```json
{
  "messages": [
    ...previous messages...,
    {
      "role": "tool",
      "tool_call_id": "call_abc123",
      "content": "File contents: ..."
    }
  ]
}
```

### 2.3 Gateway Abstraction Implementation

```rust
/// The tool_protocol.rs module provides provider-agnostic tool handling.
/// Location: bugswarm-gateway/src/gateway/tool_protocol.rs

use std::collections::HashMap;
use serde::{Deserialize, Serialize};
use serde_json::Value;

/// Converts BugSwarm ToolDefinitions to provider-specific schemas.
pub trait ToolSchemaConverter: Send + Sync {
    /// Convert a single tool definition to the provider-specific format.
    fn convert_tool(&self, tool: &ToolDefinition) -> Value;

    /// Convert all registered tools to the provider-specific format.
    fn convert_all_tools(&self, tools: &[ToolDefinition]) -> Value {
        Value::Array(tools.iter().map(|t| self.convert_tool(t)).collect())
    }

    /// Parse a tool call from the provider's response format.
    fn parse_tool_call(&self, response: &Value) -> Result<Vec<ToolCall>, ParseError>;

    /// Format a tool result for sending back to the provider.
    fn format_tool_result(&self, call_id: &str, result: &ToolResult) -> Value;

    /// Get the provider identifier for telemetry.
    fn provider_name(&self) -> &'static str;
}

/// OpenAI-compatible tool schema converter.
pub struct OpenAiToolConverter;

impl ToolSchemaConverter for OpenAiToolConverter {
    fn convert_tool(&self, tool: &ToolDefinition) -> Value {
        json!({
            "type": "function",
            "function": {
                "name": tool.name,
                "description": tool.description,
                "parameters": tool.parameters
            }
        })
    }

    fn parse_tool_call(&self, response: &Value) -> Result<Vec<ToolCall>, ParseError> {
        let choices = response["choices"].as_array()
            .ok_or(ParseError::MissingField("choices"))?;

        let mut calls = Vec::new();
        for choice in choices {
            if let Some(tool_calls) = choice["message"]["tool_calls"].as_array() {
                for tc in tool_calls {
                    calls.push(ToolCall {
                        id: tc["id"].as_str().unwrap_or("unknown").to_string(),
                        name: tc["function"]["name"].as_str()
                            .ok_or(ParseError::MissingField("function.name"))?
                            .to_string(),
                        arguments: serde_json::from_str(
                            tc["function"]["arguments"].as_str()
                                .unwrap_or("{}")
                        )?,

fn parse_xml_tool_calls(content: &str) -> Result<Vec<ToolCall>, ParseError> {

                .ok_or(ParseError::MissingField("name"))?
                .to_string(),
            arguments: parsed["arguments"].clone(),
            provider_raw: parsed,
        });
    }
```

## 3. Enterprise Upgrade: Dynamic Tool Discovery

### 3.1 Problem

Static tool definitions hardcoded in configuration mean:
- Adding a new tool requires code changes and redeployment
- Tools cannot adapt to the current context (e.g., language-specific tools)
- The model receives ALL tools even when most are irrelevant
- Custom tools from plugins cannot be registered at runtime

### 3.2 Solution: Dynamic Tool Discovery

Tools register their capabilities at runtime. The agent receives a FULL
capability list filtered to only relevant tools for the current task.

```rust
/// Dynamic tool capability.
pub trait DynamicTool: Send + Sync {
    /// Unique tool name
    fn name(&self) -> &str;

    /// Human-readable description
    fn description(&self) -> &str;

    /// JSON Schema for parameters
    fn parameters(&self) -> ToolParameters;

    /// Check if this tool is applicable to the current context
    fn is_applicable(&self, context: &AgentContext) -> bool;

    /// Priority (higher = more relevant, used for tool ordering)
    fn priority(&self, context: &AgentContext) -> u8;

    /// Execute the tool with validated arguments
    async fn execute(&self, args: Value, ctx: &ExecutionContext) -> Result<ToolResult>;

    /// Get tool category for grouping
    fn category(&self) -> ToolCategory;

    /// Get tool version for compatibility
    fn version(&self) -> semver::Version;

    /// Whether this tool requires sandbox isolation
    fn requires_sandbox(&self) -> bool;
}

/// Capability-based tool selection for the current agent task.
pub struct CapabilityBasedToolSelector {
    /// All registered tools (from plugins, core, extensions)
    all_tools: Vec<Box<dyn DynamicTool>>,

    /// Maximum number of tools to include in a single prompt
    /// (Anthropic limit: ~128, OpenAI limit: 128)
    max_tools_per_prompt: usize,
}

impl CapabilityBasedToolSelector {
    /// Select tools applicable to the current agent context.
    /// Filters by language, project type, task type, and security level.
    pub fn select_tools(&self, context: &AgentContext) -> Vec<ToolDefinition> {
        let mut applicable: Vec<_> = self.all_tools.iter()
            .filter(|t| t.is_applicable(context))
            .collect();

        // Sort by priority (descending)
        applicable.sort_by_key(|t| std::cmp::Reverse(t.priority(context)));

        // Truncate to max
        applicable.truncate(self.max_tools_per_prompt);

        // Convert to ToolDefinition for provider schema conversion
        applicable.iter().map(|t| ToolDefinition {
            name: t.name().to_string(),
            description: t.description().to_string(),
            parameters: t.parameters(),
            constraints: ToolConstraints {
                max_duration_ms: 30000,
                required_permission: PermissionLevel::Read,
                max_concurrent: 5,
                allowed_paths: vec![],
                disallowed_paths: vec![],
                rate_limit_per_minute: Some(60),
            },
            metadata: ToolMetadata {
                version: t.version().to_string(),
                category: t.category(),
                is_destructive: false,
                requires_sandbox: t.requires_sandbox(),
                author: "bugswarm".to_string(),
            },
        }).collect()
    }

    /// Register a new tool at runtime (from a plugin).
    pub fn register_tool(&mut self, tool: Box<dyn DynamicTool>) {
        tracing::info!(
            tool_name = tool.name(),
            tool_version = %tool.version(),
            "Registering dynamic tool"
        );
        self.all_tools.push(tool);
    }

    /// Generate a system prompt section describing available tools.
    pub fn generate_tool_prompt(&self, tools: &[ToolDefinition]) -> String {
        let mut prompt = String::from(
            "## Available Tools\n\nYou have access to the following tools. "
        );
        prompt.push_str("To use a tool, output a JSON object with 'name' and 'arguments'.\n\n");

        for tool in tools {
            prompt.push_str(&format!("### {}\n", tool.name));
            prompt.push_str(&format!("{}\n", tool.description));
            prompt.push_str("**Parameters:**\n");
            for (name, prop) in &tool.parameters.properties {
                let required = if tool.parameters.required.contains(name) {
                    " (required)"
                } else {
                    ""
                };
                prompt.push_str(&format!(
                    "- `{}`: {} — {}{}\n",
                    name, prop.param_type, prop.description, required
                ));
            }
            prompt.push('\n');
        }
        prompt
    }
}
```

```rust
pub struct PluginToolLoader {
    plugin_dir: PathBuf,
    loaded_libraries: Vec<libloading::Library>,

impl PluginToolLoader {
    /// Discover and load all tool plugins from the plugin directory.
    pub fn discover(&mut self) -> Result<Vec<Box<dyn DynamicTool>>, PluginError> {
        let mut tools = Vec::new();

        for entry in std::fs::read_dir(&self.plugin_dir)? {
            let entry = entry?;
            let path = entry.path();

            // Load .so / .dylib / .dll files
            if path.extension().map_or(false, |ext| {
                ext == "so" || ext == "dylib" || ext == "dll"
            }) {
                unsafe {
                    let lib = libloading::Library::new(&path)?;

                    // Each plugin exports: get_tool_count() and get_tool(index)
                    let get_count: libloading::Symbol<
                        unsafe extern "C" fn() -> u32
                    > = lib.get(b"get_tool_count")?;

                    let count = get_count();
                    for i in 0..count {
                        let get_tool: libloading::Symbol<
                            unsafe extern "C" fn(u32) -> *mut dyn DynamicTool
                        > = lib.get(b"get_tool")?;

                        let tool_ptr = get_tool(i);
                        if !tool_ptr.is_null() {
                            let tool = Box::from_raw(tool_ptr);
                            tracing::info!(
                                "Loaded tool plugin: {}",
                                tool.name()
                            );
                            tools.push(tool);
                        }
                    }

                    // Keep library loaded (must not drop)
                    self.loaded_libraries.push(lib);
                }
            }
        }

        Ok(tools)
    }
}
```

## 4. Enterprise Upgrade: Tool Result Streaming

### 4.1 Problem

In the current implementation, the model must wait for ALL tool executions to
complete before receiving results. This is problematic for:
- Long-running tools (code compilation, test suites)
- Tools that produce partial results incrementally (code search)
- User experience: no visual feedback while tools execute

### 4.2 Solution: Streaming Intermediate Results

```rust
/// Streaming tool result sender.
/// Allows tools to send partial results mid-execution.
pub struct StreamingToolExecutor {
    /// Channel to send partial results to the gateway
    stream_tx: mpsc::Sender<ToolResultChunk>,
    stream_rx: mpsc::Receiver<ToolResultChunk>,
}

/// A chunk of a tool result, sent as it becomes available.
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct ToolResultChunk {
    /// The tool call ID this chunk belongs to
    pub call_id: String,

    /// Sequence number (0-based, monotonically increasing)
    pub sequence: u64,

    /// Whether this is the final chunk
    pub is_final: bool,

    /// The partial result content
    pub content: String,
}

impl StreamingToolExecutor {
    /// Execute a tool with streaming output.
    /// Partial results are sent via the stream channel.
    pub async fn execute_streaming(
        &self,
        tool_call: &ToolCall,
        tool: &dyn DynamicTool,
        ctx: &ExecutionContext,
    ) -> Result<ToolResult> {
        let call_id = tool_call.id.clone();
        let stream_tx = self.stream_tx.clone();

        // Spawn tool execution in a task
        let handle = tokio::spawn(async move {
            // The tool can call stream_tx.send() for partial results
            let result = tool.execute(tool_call.arguments.clone(), ctx).await;
            result
        });

        // Stream partial results to the gateway
        // The gateway forwards them to the SSE connection
        let mut sequence = 0u64;
        while let Some(chunk) = self.stream_rx.recv().await {
            // Forward chunk to the SSE stream for real-time UI updates
            // The model does NOT receive these chunks — they're for the user
            // Only the final result is sent to the model
            sequence += 1;
        }

        // Wait for final result
        let final_result = handle.await??;

        Ok(final_result)
    }
}
```

## 5. Enterprise Upgrade: Parallel Tool Execution

### 5.1 Problem

Models can request multiple tools simultaneously (e.g., "read file A and file B
and run test C"). Executing these sequentially wastes time and increases latency.

### 5.2 Solution: Concurrent Tool Execution

```rust
/// Parallel tool executor that runs multiple tool calls concurrently.
pub struct ParallelToolExecutor {
    /// Maximum concurrent tool executions
    max_concurrent: usize,

    /// Semaphore to limit concurrency
    semaphore: Arc<tokio::sync::Semaphore>,
}

impl ParallelToolExecutor {
    /// Execute multiple tool calls in parallel.
    /// Tools that are independent (different resources) run concurrently.
    /// Tools that conflict (same resource) are serialized.
    pub async fn execute_batch(
        &self,
        tool_calls: Vec<ToolCall>,
        tools: &HashMap<String, &dyn DynamicTool>,
        ctx: &ExecutionContext,
    ) -> Result<Vec<ToolResult>> {
        // 1. Group tool calls by resource to detect conflicts
        let groups = self.group_by_resource(&tool_calls);

        // 2. Execute each group's tools in parallel within the group
        //    but sequential between groups that share resources
        let mut results = Vec::new();

        for group in groups {
            let group_futures: Vec<_> = group.iter().map(|call| {
                let sem = self.semaphore.clone();
                let tool = tools.get(&call.name)
                    .ok_or_else(|| ExecutionError::UnknownTool(call.name.clone()));

                async move {
                    let _permit = sem.acquire().await?;
                    match tool {
                        Ok(t) => t.execute(call.arguments.clone(), ctx).await,
                        Err(e) => Ok(ToolResult {
                            success: false,
                            content: String::new(),
                            error: Some(ToolError {
                                code: "UNKNOWN_TOOL".to_string(),
                                message: e.to_string(),
                                details: None,
                            }),
                            metadata: ToolResultMetadata::default(),
                        }),
                    }
                }
            }).collect();

            let group_results = futures::future::join_all(group_futures).await;
            results.extend(group_results.into_iter().filter_map(|r| r.ok()));
        }

        Ok(results)
    }

    /// Group tool calls by the resources they access.
    /// Calls that access the same file are serialized.
    /// Calls that access different files can run in parallel.
    fn group_by_resource(&self, calls: &[ToolCall]) -> Vec<Vec<ToolCall>> {
        use std::collections::HashSet;

        let mut groups: Vec<Vec<ToolCall>> = Vec::new();
        let mut used_resources: HashSet<String> = HashSet::new();

        let mut current_group = Vec::new();
        let mut group_resources = HashSet::new();

        for call in calls {
            let resources = self.extract_resources(call);

            // Check if this call's resources conflict with current group
            let conflicts = resources.iter().any(|r| group_resources.contains(r));

            if conflicts && !current_group.is_empty() {
                // Start a new parallel group
                groups.push(std::mem::take(&mut current_group));
                group_resources.clear();
            }

            current_group.push(call.clone());
            group_resources.extend(resources);
        }

        if !current_group.is_empty() {
            groups.push(current_group);
        }

        groups
    }

    /// Extract the resource identifiers from a tool call.
    fn extract_resources(&self, call: &ToolCall) -> HashSet<String> {
        let mut resources = HashSet::new();

        // File path tools
        if let Some(path) = call.arguments.get("path").and_then(|v| v.as_str()) {
            resources.insert(format!("file:{}", path));
        }
        if let Some(paths) = call.arguments.get("paths").and_then(|v| v.as_array()) {
            for p in paths {
                if let Some(s) = p.as_str() {
                    resources.insert(format!("file:{}", s));
                }
            }
        }

        // Sandbox tools
        if let Some(id) = call.arguments.get("sandbox_id").and_then(|v| v.as_str()) {
            resources.insert(format!("sandbox:{}", id));
        }

        resources
    }
}
```

```rust
/// H17-EXT-001: Path Traversal Prevention
/// Prevents tools from accessing files outside allowed directories.
pub struct PathTraversalValidator {
    allowed_roots: Vec<PathBuf>,
    blocked_patterns: Vec<regex::Regex>,
}

#[async_trait]
impl ToolValidator for PathTraversalValidator {
    fn name(&self) -> &str { "h17-path-traversal" }

    async fn validate(
        &self,
        call: &ToolCall,
        tool: &dyn DynamicTool,
        _ctx: &ExecutionContext,
    ) -> Result<(), ValidationError> {
        // Extract all path parameters from the tool call
        let paths = self.extract_paths(call);

        for path in &paths {
            let canonical = path.canonicalize().unwrap_or(path.clone());

            // Check if path is within allowed roots
            let allowed = self.allowed_roots.iter().any(|root| {
                canonical.starts_with(root)
            });

            if !allowed {
                return Err(ValidationError {
                    code: "H17-EXT-001-PATH_TRAVERSAL".to_string(),
                    message: format!(
                        "Path '{}' is outside allowed roots. Allowed: {:?}",
                        path.display(), self.allowed_roots
                    ),
                    severity: H17Severity::Critical,
                    details: Some(json!({
                        "path": path.to_string_lossy(),
                        "canonical": canonical.to_string_lossy(),
                        "allowed_roots": self.allowed_roots.iter()
                            .map(|p| p.to_string_lossy().to_string())
                            .collect::<Vec<_>>(),
                    })),
                });
            }

            // Check against blocked patterns
            let path_str = path.to_string_lossy();
            for pattern in &self.blocked_patterns {
                if pattern.is_match(&path_str) {
                    return Err(ValidationError {
                        code: "H17-EXT-001-BLOCKED_PATTERN".to_string(),
                        message: format!(
                            "Path '{}' matches blocked pattern '{}'",
                            path_str, pattern
                        ),
                        severity: H17Severity::Critical,
                        details: Some(json!({
                            "path": path_str,
                            "pattern": pattern.to_string(),
                        })),
                    });
                }
            }
        }

        Ok(())
    }
}

/// H17-EXT-002: Argument Type Validation
/// Ensures tool arguments match the expected JSON Schema.
pub struct ArgumentTypeValidator;

#[async_trait]
impl ToolValidator for ArgumentTypeValidator {
    fn name(&self) -> &str { "h17-arg-type" }

    async fn validate(
        &self,
        call: &ToolCall,
        tool: &dyn DynamicTool,
        _ctx: &ExecutionContext,
    ) -> Result<(), ValidationError> {
        let schema = tool.parameters();

        // Use jsonschema crate to validate arguments against schema
        let schema_value = serde_json::to_value(&schema)?;
        let compiled = jsonschema::JSONSchema::compile(&schema_value)
            .map_err(|e| ValidationError {
                code: "H17-EXT-002-SCHEMA_COMPILE".to_string(),
                message: format!("Failed to compile schema: {}", e),
                severity: H17Severity::Critical,
                details: None,
            })?;

        let result = compiled.validate(&call.arguments);
        if let Err(errors) = result {
            let error_messages: Vec<String> = errors
                .map(|e| format!("{}: {}", e.instance_path, e))
                .collect();

            return Err(ValidationError {
                code: "H17-EXT-002-TYPE_MISMATCH".to_string(),
                message: format!(
                    "Tool '{}' arguments failed validation: {}",
                    call.name,
                    error_messages.join("; ")
                ),
                severity: H17Severity::High,
                details: Some(json!({
                    "tool": call.name,
                    "errors": error_messages,
                    "received": call.arguments,
                })),
            });
        }

        Ok(())
    }
}
```

```rust
/// Telemetry collector that batches and exports tool call records.
pub struct ToolTelemetryCollector {
    /// Batch buffer
    buffer: Arc<Mutex<Vec<ToolCallTelemetry>>>,

    /// Export channel
    export_tx: mpsc::Sender<Vec<ToolCallTelemetry>>,

    /// Maximum batch size before export
    max_batch_size: usize,

    /// Maximum time before flush
    flush_interval: tokio::time::Duration,
}

impl ToolTelemetryCollector {
    /// Record a tool call.
    pub async fn record(&self, telemetry: ToolCallTelemetry) {
        let mut buffer = self.buffer.lock().await;
        buffer.push(telemetry);

        if buffer.len() >= self.max_batch_size {
            let batch = std::mem::take(&mut *buffer);
            drop(buffer);
            let _ = self.export_tx.send(batch).await;
        }
    }

    /// Start the background flush task.
    pub fn start_flush_task(&self) -> tokio::task::JoinHandle<()> {
        let buffer = self.buffer.clone();
        let export_tx = self.export_tx.clone();
        let interval = self.flush_interval;

        tokio::spawn(async move {
            loop {
                tokio::time::sleep(interval).await;
                let mut buf = buffer.lock().await;
                if !buf.is_empty() {
                    let batch = std::mem::take(&mut *buf);
                    drop(buf);
                    let _ = export_tx.send(batch).await;
                }
            }
        })
    }
}
```

```rust
/// The main chat endpoint exposed by the Gateway.
/// Handles the complete tool calling lifecycle.
#[derive(Debug, Deserialize)]
pub struct ChatRequest {
    /// User's message
    pub message: String,

    /// Conversation history (for multi-turn)
    #[serde(default)]
    pub history: Vec<ChatMessage>,

    /// Provider selection (auto-detect if not specified)
    pub provider: Option<ProviderId>,

    /// Model selection (auto-select if not specified)
    pub model: Option<String>,

    /// Maximum tool call iterations (prevents infinite loops)
    #[serde(default = "default_max_iterations")]
    pub max_tool_iterations: u32,

    /// Whether to stream tool results to the client
    #[serde(default)]
    pub stream_tool_results: bool,

    /// Tags for telemetry
    #[serde(default)]
    pub tags: HashMap<String, String>,
}

fn default_max_iterations() -> u32 { 25 }

#[derive(Debug, Serialize)]
#[serde(tag = "type")]
pub enum ChatEvent {
    /// Plain text from the model
    Text {
        content: String,
    },

    /// The model requested a tool execution
    ToolCall {
        call_id: String,
        name: String,
        arguments: Value,
    },

    /// A tool execution result (partial, if streaming)
    ToolResult {
        call_id: String,
        content: String,
        is_final: bool,
    },

    /// The final answer from the agent
    Done {
        message: String,
        total_tool_calls: u32,
        total_duration_ms: u64,
    },

    /// An error occurred
    Error {
        code: String,
        message: String,
    },
}

async fn handle_chat(
    State(state): State<Arc<GatewayState>>,
    Json(req): Json<ChatRequest>,
) -> Result<Sse<impl Stream<Item = Result<Event, Infallible>>>, AppError> {
    let stream = async_stream::stream! {
        let agent = state.agent_pool.acquire().await?;
        let tool_selector = &state.tool_selector;
        let tool_executor = &state.tool_executor;
        let telemetry = &state.telemetry;

        // 1. Select applicable tools for this request
        let context = AgentContext::from_request(&req);
        let tools = tool_selector.select_tools(&context);

        // 2. Build the conversation with system prompt + tools
        let mut conversation = Conversation::new(
            &req.message,
            &tools,
            &req.history,
        );

        // 3. Tool calling loop
        let mut iteration = 0u32;
        let mut total_tool_calls = 0u32;
        let start_time = std::time::Instant::now();

        loop {
            if iteration >= req.max_tool_iterations {
                yield ChatEvent::Error {
                    code: "MAX_ITERATIONS".to_string(),
                    message: "Agent exceeded maximum tool call iterations".to_string(),
                }.into();
                break;
            }
            iteration += 1;

            // 3a. Send conversation to model
            let response = state.provider.send(&conversation).await?;

            // 3b. Check for tool calls
            let tool_calls = response.tool_calls();
            if tool_calls.is_empty() {
                // Model produced a final answer
                yield ChatEvent::Done {
                    message: response.content().to_string(),
                    total_tool_calls,
                    total_duration_ms: start_time.elapsed().as_millis() as u64,
                }.into();
                break;
            }

            // 3c. Execute tools (possibly in parallel if model requested multiple)
            total_tool_calls += tool_calls.len() as u32;

            // Notify client about tool calls
            for call in &tool_calls {
                yield ChatEvent::ToolCall {
                    call_id: call.id.clone(),
                    name: call.name.clone(),
                    arguments: call.arguments.clone(),
                }.into();
            }

            // Execute all tools
            let results = tool_executor
                .execute_batch(&tool_calls, &context)
                .await;

            // Send results back to client
            for (call, result) in tool_calls.iter().zip(results.iter()) {
                let mut record = ToolCallTelemetry {
                    trace_id: conversation.trace_id.clone(),
                    span_id: uuid::Uuid::new_v4().to_string(),
                    parent_span_id: "".to_string(),
                    requested_at: chrono::Utc::now(),
                    started_at: chrono::Utc::now(),
                    completed_at: chrono::Utc::now(),
                    duration_ms: result.metadata.duration_ms,
                    tool_name: call.name.clone(),
                    tool_version: "1.0.0".to_string(),
                    provider: state.provider.name().to_string(),
                    model: state.provider.model().to_string(),
                    arguments_summary: summarize_arguments(&call.arguments),
                    success: result.success,
                    error_code: result.error.as_ref().map(|e| e.code.clone()),
                    error_message: result.error.as_ref().map(|e| e.message.clone()),
                    validation_results: vec![],
                    result_size_bytes: Some(result.content.len() as u64),
                    sandbox_used: result.metadata.sandbox_id.is_some(),
                    sandbox_id: result.metadata.sandbox_id.clone(),
                    cpu_time_ms: None,
                    peak_memory_bytes: None,
                    disk_read_bytes: result.metadata.bytes_read,
                    disk_write_bytes: result.metadata.bytes_written,
                    rate_limit_remaining: None,
                    rate_limit_reset_at: None,
                    agent_id: "".to_string(),
                    user_id: None,
                    project_id: None,
                };
                telemetry.record(record).await;

                yield ChatEvent::ToolResult {
                    call_id: call.id.clone(),
                    content: result.content.clone(),
                    is_final: true,
                }.into();

                // Add result to conversation for next model turn
                conversation.add_tool_result(&call.id, &result);
            }
        }
    };

    Ok(Sse::new(stream))
}
```

## 12. Summary

This document defines the complete architecture for BugSwarm's tool calling
system. The critical clarification is that frontier models DO NOT bring their
own tools — they generate text patterns that BugSwarm interprets as tool calls.

The architecture provides:
1. **Provider abstraction**: One tool definition, automatically converted to OpenAI, Anthropic, DeepSeek, or Gemini format
2. **Dynamic discovery**: Tools register at runtime, model gets filtered capability list
3. **Parallel execution**: Multiple tools execute concurrently with resource conflict detection
4. **Streaming results**: Partial tool results shown to users in real-time
5. **H17 validation**: Every tool call validated before execution
6. **Comprehensive telemetry**: Every tool call logged with latency, model, and validation results

The 6-week, 2-engineer plan is achievable with the existing Gateway and Agent
infrastructure.

### Post-MVP Enhancement (Not in this plan)

After the tool calling architecture is stable (v1.5.0+), the next enhancement is:
- **Tool result caching**: Cache deterministic tool results (same file, same content) to avoid redundant model calls
- **Tool composition**: Allow models to request tool pipelines (tool A output -> tool B input)
- **Adaptive tool selection**: ML-based tool relevance ranking based on task context
- **Tool cost tracking**: Per-tool cost attribution for billing and optimization
